# 0.1.1 release review

- Review date: 2026-09-10.
- Package: `mosh-client` 0.1.1, MIT OR Apache-2.0.
- Implementation baseline:
  `ae86bfea2da48ddfe36e7c29882e72be144f3327`.
- Status: release candidate; formal GitHub publication is authorized.
- Minimum Rust version: 1.88.0.
- Release channel: an immutable `v0.1.1` Git tag and GitHub Release with the
  inspected source package and SHA-256 checksum. No crates.io upload.

## Release decision

Version 0.1.1 is a narrow reliability release. It preserves an established
Session when UDP send or receive reports one of five explicit local I/O
categories, including the physically observed `PermissionDenied`. Failed sends
remain uncommitted. Failed receives retry through the existing bounded RTO
cadence. Both paths retain the same socket and protocol state until
authenticated peer progress confirms recovery.

Initial connection failures and unlisted I/O categories remain explicit. The
release does not change the public API, dependency versions, protocol format,
compatibility scope, or resource limits.

## Evidence boundary

Deterministic crate tests inject `PermissionDenied` at both private UDP
boundaries. They cover pacing, same-socket authenticated recovery, initial and
unlisted fatal errors, prompt cancellation, the four-second close bound, and
two-Session isolation. Stock 1.4.0 recovery remains a separate black-box gate.

LeanTTY used the implementation baseline in one real lid-close run, but
HarmonyOS destroyed and replaced the client process. That run passed LeanTTY's
workspace-restoration checks; it did not preserve the original Mosh Session or
remote PTY and captured no `PermissionDenied`. It neither confirms nor rejects
same-Session recovery in this release.

## Publication plan

Create the release from one clean candidate commit. Push that commit and the
annotated `v0.1.1` tag without changing `v0.1.0`. Attach the exact inspected
`.crate` archive and a `SHA256SUMS` file to a public, non-prerelease GitHub
Release. Read back the remote tag, release metadata, and asset digest before
calling the version published.

The repository permits crates.io as a manifest source, but the established
release channel did not upload 0.1.0 to a registry. This release follows that
channel and does not invoke `cargo publish` without `--dry-run`.
